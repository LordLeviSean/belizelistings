## Architecture Decisions

### Mobile ≤800px — separate layout

- JavaScript layout gate: `window.matchMedia("(max-width: 800px)")` in `index.js` sets `mobileLayout`.
- CSS mirrors the same breakpoint in `HomeMapFirst.module.css` and `SiteNavUnified.module.css`.
- At ≤800px, `.heroMapDesktop` is hidden; map renders in `.mobileMapSection` instead.
- Rationale: hero copy and stats remain readable without compressing the map; map gets a dedicated atmospheric band with room for the full Belize SVG.

### Portal drawer (SiteNav)

- Mobile account drawer uses React `createPortal` so the sheet escapes nav stacking context and z-index conflicts.
- Body scroll lock via `site-nav-drawer-open` class and inline `overflow: hidden` (with scrollbar gap compensation for iOS).
- Drawer only opens for authenticated users (`canShowMobileDrawer`); signed-out users use login affordances in the primary pill row.

### Breakpoint tokens (`tokens.css`)

Reference widths live in `src/styles/tokens.css` as CSS custom properties for documentation and consistent `@media` authoring:

| Token | Width |
|-------|-------|
| `--bp-phone-sm` | 390px |
| `--bp-phone-md` | 393px |
| `--bp-phone-lg` | 414px |
| `--bp-phone-xl` | 430px |
| `--bp-tablet-sm` | 768px |
| `--bp-tablet-md` | 820px |
| `--bp-desktop-sm` | 1024px |
| `--bp-desktop-md` | 1280px |
| `--bp-desktop-lg` | 1440px |
| `--bp-desktop-xl` | 1920px |

**Layout breakpoint:** 800px (nav + homepage); not identical to token names — intentional product breakpoint for nav/mobile drawer and homepage column split.

### Additional responsive hooks

- Compact search placeholder at ≤760px (`compactSearchPlaceholder` in `index.js`).
- Featured carousel image sizes: `(max-width: 760px) 82vw, 296px`.

## Homepage Philosophy

- **Quiet luxury** — calm coastal palette, sea-glass surfaces, editorial hierarchy; no loud SaaS chrome.
- **Belize-first** — national property map, district exploration, region-aware copy and stats.
- **Editorial** — kicker/headline/trust-line rhythm; section titles with subtitles; restrained motion.
- **Map-first discovery** — interactive Belize map is the hero anchor on desktop and a dedicated exploration band on mobile.
- **High trust** — verified listings messaging, real-time stats, agent/community CTA.
- **Mobile-first usability** — content order optimized for thumb reach; 44px touch targets; reduced motion respected for featured carousel.
- **Reduction over addition** — shared tokens, reused card language, minimal one-off styles.

## Mobile Architecture

**Content order (≤800px):**

1. **Nav** — `SiteNav` (brand, Favorites, Account/Login pills; drawer when signed in)
2. **Hero** — copy block (kicker, H1, trust line, subtext)
3. **Search** — inline search shell with filter button → `HomeAdvancedFiltersModal`
4. **Stats** — four stat cards (Active, For Sale, For Rent, Real-time)
5. **Map section** — `.mobileMapSection` with district caption, `BelizeMap`, tap hint
6. **Featured** — horizontal auto-scroll carousel (pauses on hover)
7. **Community CTA + Recently added** — side-by-side community card and recent grid

Global **Footer** renders via `_app.js` after page content.

---

## Desktop Architecture

**Two-column atmospheric hero (>800px):**

- **Left column** — hero copy, search shell, stat grid
- **Right column** — embedded `BelizeMap` in `.heroMapDesktop` with “Explore by district” caption
- **Sea Flow** — optional animated atmosphere layers controlled by `useSeaFlowMode` / `useSeaFlowIntensity`
- **Ambient palm backdrop** — `AmbientPalmBackdrop` fixed behind page content
- Featured carousel and community/recent sections stack below the hero canvas within `pageMain` (max-width ~1280px).

## QA Pipeline

Scripts live under `scripts/qa/` and are exposed via `package.json`:

| Command | Purpose |
|---------|---------|
| `npm run qa` | Full suite: mobile → desktop → screenshots → lighthouse |
| `npm run qa:mobile` | Signed-out smoke at 390, 393, 414, 430px + a11y role audit + PNG captures |
| `npm run qa:desktop` | Signed-out smoke at 1280×800; verifies desktop nav visibility |
| `npm run qa:screenshots` | Visual regression: signed out/in, drawer, notifications, Sea Flow levels |
| `npm run qa:lighthouse` | Lighthouse performance pass (optional; non-blocking in `qa` summary) |
| `npm run qa:visual` | Visual comparison workflow |

**Configuration:** `scripts/qa/config.mjs` — `QA_BASE_URL` defaults to `https://belizelistings.bz`; signed-in flows require `QA_EMAIL` and `QA_PASSWORD`.

**Output:** Timestamped runs under `qa-screenshots/qa-runs/`; regression manifest under `qa-screenshots/regression/`.

**Smoke checks (signed-out):** brand link, H1, searchbox, Favorites nav link; page error and console error collection.

## Testing Strategy

1. **Build gate** — `npm run build` must pass before release tags.
2. **Unit tests** — `npm test` (Jest) for contracts, canonical listing, persistence layers.
3. **QA automation** — run `npm run qa:mobile` and `npm run qa:desktop` against production or `QA_BASE_URL` staging.
4. **Visual regression** — `npm run qa:screenshots` when changing shared chrome (nav, Sea Flow); homepage frozen, so primarily for regression detection.
5. **Manual spot-check** — verify at reference widths: 390, 393, 414, 430, 768, 820, 1024, 1280, 1440, 1920.
6. **Accessibility** — QA role audit (unlabeled buttons, missing `alt`); manual keyboard pass on search, filters modal, favorites, map district links.
7. **Production verification** — post-deploy smoke on `belizelistings.bz` homepage: hero, search submit → `/search`, district map navigation → `/listings/district/[slug]`.

## Homepage Design Principles

1. **Quiet luxury** — sea-glass, soft gradients, no dark panels or loud chrome
2. **Belize-first identity** — map, districts, national scope in copy and interaction
3. **Editorial typography** — DM Sans wordmark in nav; clamp-based headline scaling on mobile
4. **Atmospheric Sea Flow** — optional motion layers; intensity as CSS variable
5. **Glass interface** — blur, inset highlights, `--ui-shadow-*` tokens in `HomeMapFirst.module.css`
6. **Mobile-first usability** — content order, touch targets, dedicated map band
7. **Spacing system** — aligned with `--site-nav-offset`, page gaps, stat grid rhythm
8. **Responsive integrity** — explicit mobile/desktop split at 800px, not accidental collapse
9. **High trust** — stats from live listings, verification messaging, agent community CTA

## Future Homepage Policy

After `v1.0-homepage`, the homepage is **frozen**. Permitted changes:

- **Bug fixes** — functional regressions, layout breakage, data display errors
- **Accessibility** — WCAG gaps, focus management, labels, contrast fixes
- **Performance** — bundle size, image loading, carousel jank, Core Web Vitals
- **SEO** — meta tags, structured data, crawlability (without visual redesign)
- **Production issues** — incidents affecting live users on `belizelistings.bz`

**Not permitted without a new milestone:**

- Visual redesign, new sections, layout rearchitecture
- New animations, gradients, or shadow systems outside existing tokens
- Feature additions (e.g. new homepage widgets, marketing bands)
- Breakpoint or mobile/desktop split changes

Phase 2 marketplace work should target listing detail, search results, district pages, and dashboards — not homepage experimentation.
